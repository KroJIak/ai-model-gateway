# Model Bridge

Единый OpenAI-совместимый мост. Любая chat-панель подключается один раз
и видит все модели, не зная, как они устроены внутри.

## Сервисы

| Сервис | Назначение | Модели |
|---|---|---|
| `gpt-api` | CLIProxyAPI — те же запросы, что отправляет Codex CLI | только `gpt-*` |
| `grok-cli-api` | Grok Build CLI как API — агентский цикл CLI | все остальные (grok, gemini, китайские и т.д.), список подтягивается из каталога провайдера |
| `model-bridge` | агрегатор: один endpoint, ключ, маршрутизация | всё из включённых бэкендов |

## Быстрый старт

```bash
cp .env.example .env       # заполнить ключами провайдера
docker compose up -d --build
```

- Внутри docker-сети: `http://model-bridge:8080/v1`
- Снаружи: поднимите внешние порты через `docker-compose.override.yml`
  (значения — в `.env`, например `http://localhost:8081/v1`)
- Авторизация: `Authorization: Bearer <BRIDGE_API_KEY из .env>`

## Маршрутизация

Правила — в `config.yaml`: бэкенды опрашиваются по порядку, модель
закрепляется за первым, кто её отдал. include/exclude — glob-паттерны.
Бэкенд выключается флагом `enabled: false`.

## Память инструментов

Если модель падает на запросе с инструментами, мост сразу повторяет его
без инструментов и запоминает модель на неделю (`TOOLS_RETRY_TTL_DAYS`):
все последующие запросы идут без инструментов без лишнего ожидания.
Успешный запрос с инструментами снимает пометку.
