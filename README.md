# Model Bridge

Единый OpenAI-совместимый мост над несколькими CLI-API сервисами.
Каждый сервис оборачивает официальное CLI-окружение своей модели
(gemini-cli, grok-build, ...) в OpenAI-совместимый API, а мост
агрегирует их в один endpoint для любой chat-панели.

## Сервисы

| Сервис | Назначение | Модели |
|---|---|---|
| `gemini-cli-api` | официальный Gemini CLI как API (нативный поиск Google внутри CLI-цикла) | строго `gemini-*` из env |
| `grok-cli-api` | Grok Build CLI как API (агентский цикл CLI, поиск выполняется локально) | строго `grok-*` из env |
| `bridge` | агрегатор: один OpenAI endpoint над всеми сервисами, приоритет и пометки моделей | всё из включённых бэкендов |

CLIProxyAPI (GPT/other-канал) в репо не входит — мост подключается к нему
как к обычному OpenAI-бэкенду через `config.yaml`.

## Быстрый старт

```bash
cp .env.example .env       # заполнить ключами своего провайдера
cp config.example.yaml config.yaml
docker compose up -d --build
```

- Bridge: `http://localhost:8080/v1` (OpenAI-совместимый)
- Модели: `GET /v1/models` — каждая модель несёт `meta.features` (например
  `web_search: false` = у этого канала нет рабочего поиска в интернете)

## Приоритеты и маршрутизация

Бэкенды опрашиваются в порядке конфигурации; модель закрепляется за первым
бэкендом, который её отдаёт. include/exclude — glob-паттерны. Бэкенд можно
выключить флагом `enabled: false` — его модели исчезают из выдачи.

## Примечание о качестве

Поиск выполняется средой выполнения модели: у GPT-канала — серверный
web_search, у gemini/grok CLI-каналов — агентский цикл CLI. Если канал
провайдера не поддерживает поиск, модель помечается
`features.web_search: false` — потребитель метаданных может показывать
таким моделям пометку «без доступа в интернет».
